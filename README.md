# Element Digital

Многостраничный сайт существующей студии. Доработан на исходной сборке без внешних npm-зависимостей. Сохранены услуги, этапы, FAQ, контакты, иллюстрации, локальные шрифты, лицензии и интерактивный дом исходного проекта. Предыдущие исходники интерфейса остаются в `src/legacy.html`, `src/app.js`, `src/style.css`, `src/motion.*`; историческая документация — в `docs/legacy-readme.md`. Они не копируются в новую публичную сборку.

## Локальный запуск

Node.js 20+. Установка зависимостей не требуется.

```sh
npm run dev
```

Откройте `http://localhost:4173/element-digital/`. После изменений перезапустите сервер. Для локального адреса без префикса используйте `SITE_URL=https://example.test npm run dev` и открывайте `/`. Переменная задаёт публичные метаданные и базовый путь, но не адрес локального HTTP-сервера.

```sh
npm run check
npm test
npm run build:static
npm run build
```

`build:static` создаёт файлы GitHub Pages в `dist/`, включая `.nojekyll`. `build` создаёт самостоятельный серверный Worker в `dist/server/index.js`. Существующая серверная конфигурация сохранена. Не публикуйте ветку до визуального согласования.

## Формы

На GitHub Pages серверный код не выполняется. Без `PUBLIC_LEADS_ENDPOINT` форма валидирует поля и согласие, затем показывает подготовленный текст, копирование и ссылку в существующий Telegram студии. Сообщение посетитель отправляет самостоятельно. Ложного подтверждения доставки нет. Данные не записываются в localStorage.

Для прямой доставки используйте серверную сборку с секретами `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`. Секреты передаются окружением сервера; не вставляйте их в исходники, браузер или публичные переменные. Существующий обработчик проверяет Origin, тип/размер/длины данных, согласие, honeypot, повторные обращения и подтверждение Telegram. Ограничение частоты в памяти — best effort на экземпляр, не глобальное распределённое ограничение.

Для отдельного backend:

```sh
SITE_URL=https://kerbalis1.github.io/element-digital PUBLIC_LEADS_ENDPOINT=https://backend.example/api/leads npm run build:static
```

На backend задайте `LEADS_ALLOWED_ORIGINS=https://kerbalis1.github.io` (без завершающего слеша). Только явно перечисленные HTTPS Origin получают CORS. Список через запятую, без wildcard. Адрес `backend.example` — пример, не готовый сервис. Пока реальный backend не настроен, используйте ручной сценарий Telegram. В тестовой среде секреты отсутствуют: реальная внешняя доставка не проверялась.

## SEO и аналитика

По умолчанию `SITE_URL=https://kerbalis1.github.io/element-digital`. При смене домена пересоберите с новым URL: canonical, OG, JSON-LD, sitemap и ссылки используют единый источник. Каждая страница имеет уникальные title/description и один H1. Демо помечены `noindex, follow` и исключены из sitemap. Изображение `og.png` сохранено из исходного проекта.

Необязательная Яндекс Метрика включается сборочной переменной `YANDEX_METRIKA_ID`. Без ID ничего внешнего не загружается. При наличии ID скрипт загружается только после согласия посетителя. Есть отказ и изменение выбора в подвале. Вебвизор и автоматический сбор ссылок/кликов отключены. События `brief_prepared` и `brief_sent` не содержат имён, контактов или текста обращения. Настройте одноимённые цели в счётчике при подключении.

Серверная сборка задаёт CSP, nosniff, Referrer-Policy, Permissions-Policy и SAMEORIGIN. GitHub Pages не позволяет задавать произвольные HTTP-заголовки из файлов; для эквивалентной политики нужен управляемый хостинг/прокси. Скрипты и шрифты локальные, опасные данные демо выводятся через textContent. Для статического хостинга CSP можно настроить на внешнем CDN, не через фиктивный `_headers`.

## Производительность и доступность

Горный фон: 91 КБ на широком экране, 30 КБ в мобильной версии. Локальные шрифты используют `font-display: swap`; изображения проектов загружаются лениво и имеют размеры. Нет фреймворка, внешних библиотек и бесконечных таймеров JavaScript для облаков. Движение облаков использует transform, останавливается кнопкой и учитывает `prefers-reduced-motion`. Демо дома сохраняет управление клавиатурой и отключает эффекты при уменьшении движения.

Семантические заголовки, landmarks, skip-link, видимый фокус, подписи полей, живые статусы, нативные details и доступное мобильное меню. Проверка мобильной компоновки — в браузере на ширине 375 px; она не заменяет проверку на физических iOS/Android-устройствах. Оценка Lighthouse/Core Web Vitals на production не измерялась.

## Проверка и выпуск

CI только проверяет и собирает архив. Он не публикует сайт. Рабочая ветка: `feat/premium-multipage`; слияние в `main` и изменение действующего хостинга — после согласования.

Перед публикацией:

1. Согласовать дизайн и тексты всех направлений.
2. Подтвердить, что сохранённый контакт `https://t.me/spectransport38` подходит студии.
3. Для прямой отправки подключить backend и проверить реальное получение одной контрольной заявки. Ручной сценарий работает без backend.
4. Дополнить информацию об обработке данных реальными сведениями оператора и согласованными сроками/условиями хранения. Текущая страница описывает поведение интерфейса и не заявлена как окончательный юридический документ.
5. При необходимости задать ID аналитики и проверить согласие/отказ на рабочем домене.
6. Собрать с окончательным `SITE_URL`, согласовать выпуск, затем развернуть. Проверить ссылки и формы на production.
