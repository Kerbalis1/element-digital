# ELEMENT DIGITAL

Готовый адаптивный сайт независимой digital-студии. Позиционирование: «Сайты и сервисы для понятной работы бизнеса». Помогаем малому и среднему бизнесу представить услуги, принимать обращения и автоматизировать процессы.

В проекте нет вымышленных клиентов, отзывов, наград, стажа и обещаний роста продаж. «Берег», «Форма» и «Поток» — авторские демонстрационные концепции. Они показывают дизайн и сценарии; это не клиентские заказы и не отдельные работающие магазины/CRM.

## Запуск

Нужен Node.js 20 или новее. Установка npm-пакетов не требуется.

```sh
npm run dev
```

Откройте `http://localhost:4173`. Команда собирает сайт перед запуском. После изменения исходников перезапустите её или выполните `npm run build` и обновите страницу. Сервер не отслеживает изменения автоматически.

```sh
npm run check   # Проверка синтаксиса JavaScript
npm run build   # Серверная сборка в dist/server/index.js
npm run start   # Просмотр уже собранной папки dist/
```

Другой порт: `PORT=8080 npm run dev` в macOS/Linux; в PowerShell задайте `$env:PORT=8080` перед запуском. Встроенный сервер предназначен для локального просмотра, а не для production.

## Где редактировать

- `src/config.js` — название, город, формат работы, контакты, SEO, первый экран, все услуги, проекты, этапы и FAQ.
- `src/index.html` — разметка, тексты разделов задач, о студии и контактной формы.
- `src/style.css` — палитра, типографика, сетка, мобильная версия и анимации.
- `src/app.js` — интерактивность, меню, окна проектов, форма.
- `public/assets/` — изображения, иконка и локальный шрифт символов.
- `scripts/build.mjs` — сборка без зависимостей; `scripts/serve.mjs` — локальный сервер.

В `site.services` массив `audienceTags` задаёт метки типов бизнеса в списке, поле `audience` — их текстовый резервный вариант, а `for` — подробное пояснение, кому подходит формат и в какой ситуации. Это примеры возможных заказчиков, не список клиентов студии.

У каждой услуги есть необязательные `price` и `timeline`. Значение `null` скрывает поле. Заполняйте их только согласованными данными. Порядок услуг и проектов определяется массивами в конфигурации.

`telegram` принимает полный URL вида `https://t.me/your_username`, `email` — настоящий адрес. Пустые значения не создают фиктивных ссылок: посетитель видит пояснение и может сохранить обращение. После изменения конфигурации выполните сборку.

Первый экран и география подставляются из конфигурации в HTML при сборке. `city` необязателен: пустая строка скрывает город и оставляет только `geography`, без лишнего разделителя. При изменении названия обновите также первоначальную разметку логотипа и подпись иконки; JavaScript подставляет название из конфигурации после загрузки.

## Изображения и SEO

Три иллюстрации проектов — оригинальные SVG: небольшой размер, чёткое отображение на Retina, без внешних запросов. Новые фотографии оптимизируйте в WebP/AVIF, указывайте размеры и содержательные alt-тексты. Превью показываются целиком, в исходных пропорциях, без обрезки и увеличения при наведении. Кнопка просмотра находится под изображением и не перекрывает макет. Поля `imageWidth` и `imageHeight` проекта задают исходные размеры и резервируют корректное место до загрузки.

Для каждого проекта укажите `image` относительно корня сайта, например `assets/my-project.webp`. Заполните `title`, `type`, `description`, `task`, `solution`, `scope`, `tags`. Текущая версия предназначена для демонстрационных работ и всегда показывает соответствующую метку. При добавлении реального кейса сначала доработайте модель статуса и отображение метки, а затем публикуйте согласованные материалы.

`site.title`, `site.description` и `site.url` подставляются в title, description, canonical и Open Graph при сборке. Укажите окончательный HTTPS-домен без завершающего слеша. `public/assets/og.png` — растровое изображение 1200×630 для соцсетей. Замените его при изменении позиционирования. Sitemap для одностраничного сайта можно добавить после выбора постоянного домена. В `robots.txt` нет запрета индексирования; приватная публикация Sites защищена доступом самой платформы.

Визуальный стиль: графитовый первый экран, слоновая кость, приглушённый цвет шампань и авторский объёмный знак E. Зелёный акцент удалён из интерфейса и демонстрационных иллюстраций.

Основной шрифт — Manrope (400/500/600), заголовки — Cormorant Garamond (400). Шрифты включены в проект в WOFF, сокращены до латиницы, кириллицы и нужной пунктуации. Лицензии OFL находятся в `public/assets/MANROPE-LICENSE.txt` и `public/assets/CORMORANT-LICENSE.txt`. Символы — подмножество DejaVu Sans, лицензия в `public/assets/FONT-LICENSE.txt`. Все шрифты загружаются локально, без внешних запросов.

Типографика: основной текст 16–18 px, подписи и элементы интерфейса от 14 px. Шрифт с засечками применяется к крупным заголовкам; описания, форма и навигация используют Manrope. На телефоне длинные блоки перестраиваются в одну колонку.

Фон тёмных разделов дополнен оригинальными векторными стеклянными каплями и тонкими цифровыми линиями. Файлы: `public/assets/glass-drops.svg`, `glass-drops-mobile.svg` и `digital-traces.svg`. Параметры прозрачности и маски — в блоке `Glass droplets` в `src/style.css`. Декор не перехватывает клики, скрыт от скринридеров, остаётся статичным и приглушается при повышенном контрасте.

Цвета редактируются через переменные `--paper`, `--ink`, `--accent`, `--dark` в начале `src/style.css`. Скульптура первого экрана находится в `public/assets/element-sculpture.svg`; это оригинальная векторная иллюстрация без сторонних изображений.

## Анимированные сцены и цифровые аватары

`src/motion.css` содержит движение знака E, световой блик, парящие панели, сцену сайта/телефона и аватары. `src/motion.js` управляет паузой, положением сцены при прокрутке и отключением движения. Используются CSS и нативные браузерные API, без внешних библиотек, WebGL и фонового видео.

- Кнопка «Остановить анимацию» на первом экране останавливает автоматическое движение на всей странице. Повторное нажатие его включает.
- Настройка `prefers-reduced-motion` автоматически даёт статичную композицию. Изменение системной настройки учитывается без перезагрузки.
- Вне экрана и при скрытой вкладке анимации приостанавливаются. Прокрутка остаётся нативной; тексты и кнопки не двигаются вместе с иллюстрациями.
- Новый набор услуг — авторские 3D-иллюстрации в едином стиле стекла, жемчужной керамики и металла шампань. Все шесть изображений собраны в одном прозрачном атласе 3×2 `public/assets/service-icons-premium.webp` (1536×1024). Браузер загружает файл один раз. В `src/config.js` у каждой услуги заданы `avatar`, `avatarAtlas: true`, `avatarColumn` (0–2) и `avatarRow` (0–1). CSS показывает нужную ячейку без изменения исходного рисунка. Верхний ряд: курсор, окна, сумка. Нижний: бот, модули, сфера. При замене атласа сохраняйте сетку 3×2 и прозрачные поля вокруг каждого объекта; для отдельного SVG/изображения уберите `avatarAtlas`. Контурный набор сохранён в `public/assets/service-icons/`. Объёмные иллюстрации в анимированных сценах отдельно хранятся в `public/assets/avatars/`. Нажатие раскрывает соответствующий раздел и переводит клавиатурный фокус на его заголовок.
- Новая сцена в `src/index.html` — визуальная концепция, а не работающий клиентский сервис. Телефон, сообщения и миниатюра сайта не отправляют данные.
- Блик на E использует маску `public/assets/element-mask.svg`; при замене центрального знака замените и её.

## Интерактивный дом в концепции «Берег»

При наведении на область дома крыша, фасадные панели, каркас, дверь и основание плавно расходятся; при уходе курсора собираются. На сенсорном экране касание переключает состояние. С клавиатуры используйте Tab для выбора дома, Enter/пробел для переключения, Escape для сборки.

Разметка частей хранится в `public/assets/project-bereg.svg`; во время сборки создаётся `dist/house-art.js` для встроенного SVG. `src/house.js` управляет наведением/касанием, а блок `Bereg cabin` в `src/motion.css` задаёт расстояния и скорость разборки. При открытии проекта создаётся независимый экземпляр SVG с собственными ID. Все части остаются внутри полного макета.

Общая кнопка остановки анимации и `prefers-reduced-motion` отключают эффект и показывают собранный дом. Кнопка просмотра концепции остаётся отдельной и доступной с клавиатуры; нажатие на сам дом не открывает проект случайно.

В сцену «Берег» добавлен банный чан. При наведении на него загорается огонь снизу и поднимается пар; при уходе курсора эффект плавно гаснет. Касание или Enter/пробел переключают его, Escape и уход фокуса выключают. Огонь и пар останавливаются при скрытии вкладки, уходе сцены за экран, общей паузе и `prefers-reduced-motion`. Чан и дом управляются независимо; эффект работает в превью и в модальном окне. Геометрия — группа `.hot-tub` в SVG, анимации и область нажатия — блок `Bereg hot tub` в `src/motion.css`.

## Заявки в Telegram

Контакт студии уже установлен: `https://t.me/spectransport38`. Кнопки открывают этот аккаунт.

Сайт работает как самодостаточный Cloudflare Worker без зависимостей. `POST /api/leads` передаёт имя, контакт и задачу в Telegram через Bot API; токен существует только в серверном окружении. `GET /api/leads/status` сообщает браузеру только доступность отправки, без секретов и ID получателя.

В форме одна кнопка — «Отправить заявку». Она всегда вызывает `POST /api/leads`, без предварительного запроса статуса и без окна копирования/скачивания. В случае подтверждения `sendMessage` Telegram форма очищается и показывает успех. При ошибке поля сохраняются, а сообщение об ошибке появляется под кнопкой. При таймауте заявка могла дойти, поэтому автоматического повтора нет. Без корректных серверных секретов возвращается ошибка, а не ложный успех.

Сообщение приходит от бота и содержит имя посетителя, оставленный им контакт и описание задачи. Личность посетителя в Telegram сайт не подтверждает. В журнал попадают только числовой код ошибки Telegram и безопасная категория (`bot_credentials`, `recipient_permission`, `recipient_or_request`, `provider_rate_limit`), без токена и текста заявки.

### Настройка бота

1. В официальном `https://t.me/BotFather` выполните `/newbot`, задайте название и свободный username, заканчивающийся на `bot`. Сохраните выданный токен как секрет.
2. Из аккаунта `@spectransport38` откройте своего бота и нажмите Start. Бот не может первым начать переписку с личным аккаунтом.
3. Получите числовой ID получателя. Его можно посмотреть в ответе `getUpdates` Bot API в поле `message.chat.id` после сообщения своему боту. Запрашивайте API локально или на сервере, не вставляйте токен в браузерную адресную строку, скриншоты или публичные сервисы. Username личного аккаунта не заменяет числовой ID.
4. В серверных переменных Sites добавьте `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`, отметьте оба значения как секреты. Для подключения в этом чате можно попросить настроить серверные переменные; не размещайте токен в исходниках. После изменения переменных повторно опубликуйте сохранённую версию, чтобы применить окружение.
5. Выполните контрольную заявку с сайта и убедитесь, что она пришла в чат с вашим ботом. Только после этого отправка считается полностью подключённой.

Локально сервер читает эти же переменные из окружения процесса. Файлы `.env` игнорируются Git, но автоматически не загружаются. Для локальной проверки без отправки секреты не нужны.

Обработчик проверяет Origin, Content-Type, размер тела (12 KB), имя (100 символов), контакт (200), задачу (3000), скрытое антиспам-поле. Текст передаётся без HTML/Markdown-разметки. Есть ограничитель повторных запросов на минуту в пределах экземпляра Worker; он не является глобальным ограничителем. При публичном запуске с заметным потоком заявок добавьте централизованное ограничение или Turnstile. Таймаут Telegram — 12 секунд. Контакты и тексты не записываются в журнал или постоянное хранилище сайта.

## Публикация

Текущий хостинг — Sites. `.openai/hosting.json` сохраняет прежний `project_id`, поле `static` удалено для серверной отправки. `npm run build` собирает один ESM Worker `dist/server/index.js` и `dist/.openai/hosting.json`. Все браузерные файлы, шрифты и изображения встроены в Worker при сборке и отдаются по прежним URL. Серверные модули не выдаются посетителю. Секреты не встраиваются в сборку.

Приватность сайта сохранена. Открытие доступа всем и подключение домена — отдельные настройки владельца.

Для переноса на Cloudflare Workers используйте `dist/server/index.js` как `main` и задайте секреты через хостинг. На обычном статическом хостинге используйте `npm run build:static` и папку `dist/`; там автоматическая отправка потребует отдельного backend. После статической сборки снова выполните `npm run build` для публикации в Sites.

После выбора домена обновите `site.url` и пересоберите сайт. Команды проверки: `npm run check`, `npm test`, `npm run build`.

## Проверка

Для анимированной версии проверены 10 ширин от 320 до 1900 px, фактическое изменение трансформации знака E, остановка и возобновление движения, изменение сцены при прокрутке, системное отключение анимации без перезагрузки, работа всех шести аватаров, клавиатурный фокус и загрузка изображений. Проверки контраста текста и основных сценариев сайта также повторены.

Для обновлённой типографики дополнительно проверены размеры текста и расчётный контраст HTML-текста в основных разделах, раскрытых услугах/FAQ и окне проекта на 9 ширинах (320–1440 px). Обнаруженные недостаточно контрастные подписи исправлены. Это проверка текстовых стилей, а не полный аудит WCAG.

Проведены браузерные проверки в Chromium: ширины 320, 375, 390, 760, 768, 1024 и 1440 px, отсутствие горизонтального скролла и ошибок JavaScript, мобильная навигация, клавиатурное раскрытие услуг, FAQ, три окна проектов, Escape, валидация и подготовка обращения, копирование/резервное выделение, скачивание, изображения и внутренние ссылки, `prefers-reduced-motion`.

Вёрстка учитывает видимый фокус, подписи полей, skip-link, нативные `details` и модальные `dialog`. Полевое тестирование на настоящих устройствах, аудит WCAG и замеры на реальном хостинге остаются отдельными проверками. При развитии сайта повторяйте сценарии формы и навигации.

## Контактный блок

Обновлённый блок `contact-conversation` в `src/index.html`: приглашение к разговору, три темы обсуждения и форма на светлой панели. Стили ограничены этим блоком в конце `src/style.css`. Состояния отправки, ошибки и подтверждённого успеха оформляются через `data-state` элемента `#form-status`; при редактировании поля старое сообщение очищается. Серверная доставка остаётся прежней.

Каталог услуг `.service-catalog` оформлен общей светлой панелью. В заголовке каждой строки показаны название, краткая польза (`short`) и статичные метки бизнеса (`audienceTags`). Метки не являются кнопками. Подробности открываются нативным `details`, включая управление с клавиатуры.
